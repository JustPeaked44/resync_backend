## 2025-02-27 - SSRF via Redirects in Citation Service
**Vulnerability:** The citation service fetched potentially untrusted links provided by users. It verified the initial URL's host against private/loopback IP address ranges to prevent Server-Side Request Forgery (SSRF). However, it used `follow_redirects=True` with `httpx` without checking the redirect URLs, allowing an attacker to submit an initial safe URL that redirects to an internal one.
**Learning:** `httpx` automatically follows redirects if `follow_redirects=True` is set, but its standard interceptors do not check redirect hosts if only the initial host was checked. We need to attach event hooks to validate every request, including those triggered by redirects.
**Prevention:** Always use `event_hooks={'request': [_verify_request_host]}` on the `httpx.AsyncClient` when `follow_redirects=True` is enabled and user-supplied URLs are involved, to validate every host (including ones from redirects) against the `_is_safe_public_host` helper.
