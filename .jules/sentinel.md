## 2024-10-12 - SSRF Vulnerability in httpx Redirects
**Vulnerability:** The application was vulnerable to SSRF through HTTP redirects. Even though the initial URL host was verified to be a safe public address, `httpx` automatically followed redirects (`follow_redirects=True`) to internal/private IPs without any per-hop validation.
**Learning:** `httpx` does not expose a per-hop hook or automatically block redirects to private IPs. When `follow_redirects=True` is set, an attacker can supply a URL that passes the initial public IP check but subsequently redirects to an internal service (e.g., cloud metadata endpoints or loopback addresses).
**Prevention:** To safely handle redirects, use the `event_hooks` configuration when instantiating `httpx.Client` or `httpx.AsyncClient` (e.g., `event_hooks={'request': [_verify_request_host]}`). The hook runs on the initial request and every subsequent redirect, allowing us to enforce our safe-host constraints at every hop. For asynchronous hooks using synchronous functions like `socket.getaddrinfo`, remember to run them via `asyncio.to_thread` to avoid blocking the event loop. Also, ensure the hook raises an exception compatible with `httpx` logic, such as `httpx.ConnectError`, passing `request=request`.
