## 2024-10-24 - SSRF Vulnerability via HTTP Redirects
**Vulnerability:** A Server-Side Request Forgery (SSRF) vulnerability was discovered in `services/citation.py` where `httpx.AsyncClient` was configured with `follow_redirects=True`. The initial URL was validated against a list of safe public hosts, but the HTTP client automatically followed redirects without validating the target of the redirect. This could allow an attacker to bypass the initial check by setting up a public server that redirects to an internal/private IP address.
**Learning:** The `_is_safe_public_host` function was correctly verifying the initial host before making the HTTP request, but it was unaware of redirects handled internally by the `httpx` client. Since `httpx` does not expose a per-redirect hook easily, the solution requires intercepting every outbound request (including those generated by redirects).
**Prevention:** Always validate all outbound requests, including redirects, when making HTTP requests to user-supplied URLs. In `httpx`, this can be achieved by attaching an event hook for the `request` event (`event_hooks={'request': [hook_function]}`) to the client. This ensures that every request, regardless of whether it's the initial request or a redirect, is validated before being executed.
