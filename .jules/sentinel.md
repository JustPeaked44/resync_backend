## 2024-05-18 - SSRF Vulnerability in HTTP Redirects
**Vulnerability:** The application was vulnerable to Server-Side Request Forgery (SSRF) because it only checked the host of the initial URL before fetching it. If the initial URL redirected to an internal or private address (e.g., cloud metadata endpoints or loopback), the `httpx` client would follow the redirect, bypassing the SSRF guard.
**Learning:** This existed because `httpx` handles redirects automatically when `follow_redirects=True` is set, and the existing SSRF guard `_is_safe_public_host` was only called before the initial request, not on subsequent requests in the redirect chain.
**Prevention:** To prevent this, use `httpx`'s `event_hooks` feature to attach a request hook that validates the host on *every* request, including redirects. Ensure the hook function safely delegates synchronous DNS resolution (like `socket.getaddrinfo`) to a separate thread using `asyncio.to_thread` to avoid blocking the event loop.
