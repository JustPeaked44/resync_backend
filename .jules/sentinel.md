## 2024-05-19 - Missing SSRF Protection on HTTP Redirects
**Vulnerability:** The `CitationAuditService` in `services/citation.py` checked if the initial URL host was a safe public host to prevent SSRF. However, because `follow_redirects=True` was set on the `httpx.AsyncClient` without an event hook, a safe initial URL could redirect to an unsafe internal or private IP address, completely bypassing the SSRF protection on subsequent hops.
**Learning:** Initial URL validation is insufficient when HTTP clients automatically follow redirects.
**Prevention:** Always use client event hooks (e.g., `event_hooks={'request': [hook_function]}`) to validate the host of every request, including those generated by redirects, before the request is executed.
