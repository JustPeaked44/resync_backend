## 2024-09-25 - Prevent SSRF via Redirects in `httpx`
**Vulnerability:** The application was using `httpx.AsyncClient(follow_redirects=True)` to verify citation links. While the initial URL host was checked to prevent Server-Side Request Forgery (SSRF), if the initial URL returned an HTTP redirect to an internal IP (e.g. `169.254.169.254` or `127.0.0.1`), the `httpx` client would blindly follow it, circumventing the SSRF protection.
**Learning:** Checking the host only on the initial URL is insufficient when automatic redirect following is enabled. With `httpx`, the `event_hooks={'request': [hook_fn]}` configuration allows us to intercept and validate every HTTP request before it is made, including requests generated by automatic redirects.
**Prevention:** Whenever `follow_redirects=True` is enabled and SSRF is a concern, always attach a request hook that performs strict validation on `request.url.host` to ensure that no internal or restricted endpoints are accessed via redirects.
