## 2026-09-17 - [CRITICAL] Fix SSRF via HTTP Redirects
**Vulnerability:** The citation URL reachability check `_check_http_reachability` properly validated the initial URL host against `_is_safe_public_host` to prevent SSRF, but allowed `httpx` to follow redirects implicitly (`follow_redirects=True`). An attacker could provide a URL to a safe public host that then redirects to an internal, private, or sensitive URL (e.g., `127.0.0.1`, `169.254.169.254`).
**Learning:** `httpx`'s automatic redirect handling doesn't expose a per-hop hook to validate new URLs against an SSRF blocklist before making the subsequent request. The initial validation check is entirely bypassed for subsequent redirect requests.
**Prevention:** Always set `follow_redirects=False` when making outward requests that require SSRF protection. Manually inspect the `Location` header on 3xx responses, construct the new URL, and validate the new host against the SSRF rules before making the next hop request.
