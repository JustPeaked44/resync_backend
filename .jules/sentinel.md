## 2025-02-17 - Prevent SSRF with httpx Event Hooks
**Vulnerability:** Server-Side Request Forgery (SSRF) risk during HTTP redirects. The application checked the host of the initial URL provided to `httpx`, but it used `follow_redirects=True`, allowing malicious servers to redirect requests to internal or private IPs (e.g. cloud metadata services, 169.254.169.254), circumventing the initial host check.
**Learning:** `httpx` handles redirects automatically when `follow_redirects=True` is set, and it does not re-evaluate the initial URL validation for each redirected hop. This created a residual gap where requests could end up fetching content from unintended internal destinations.
**Prevention:** Use `event_hooks={'request': [_hook]}` on the `httpx.AsyncClient` instantiation. The hook function runs for *every* request, including any automatic redirects, allowing the `_is_safe_public_host` function to validate the host at each hop before the request is made. If a redirect attempts an SSRF attack, the hook blocks it by raising `httpx.ConnectError` (with the `request=request` parameter to satisfy httpx requirements).
