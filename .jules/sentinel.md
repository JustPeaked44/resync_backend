## 2024-05-24 - SSRF Bypass via httpx Redirects
**Vulnerability:** The SSRF guard (`_is_safe_public_host`) only validated the initial URL provided by the user. Because `httpx.AsyncClient` was configured with `follow_redirects=True`, a malicious user could provide a URL to a safe public host that responds with an HTTP redirect to an internal IP (e.g., `127.0.0.1` or `169.254.169.254`), bypassing the initial check and executing a request against internal infrastructure.
**Learning:** Checking the hostname only once before initiating a request is insufficient when the HTTP client is configured to follow redirects automatically. The underlying library's redirect handling will blindly follow the Location header to arbitrary internal addresses.
**Prevention:** Use HTTP client event hooks (like `event_hooks={'request': [_verify_request_host]}` in `httpx`) to run the SSRF verification logic on every single outbound request, including all hops in a redirect chain. When raising `httpx.ConnectError` in a hook, ensure the `request=request` kwarg is included.
