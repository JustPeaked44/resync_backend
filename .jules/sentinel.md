## 2025-02-20 - SSRF bypassed via HTTPX Redirects
**Vulnerability:** The existing Server-Side Request Forgery (SSRF) protection in `_is_safe_public_host` only verified the initial URL but failed to account for subsequent HTTP redirects when using `httpx.AsyncClient` with `follow_redirects=True`.
**Learning:** `httpx` will automatically follow redirects and does not check the host on each hop natively, leaving a blind spot where an attacker could provide a safe public URL that immediately redirects to an internal, private, or restricted IP.
**Prevention:** Always use `event_hooks={'request': [_verify_request_host]}` on the `httpx` client to intercept every request and validate the host *before* the request is sent, ensuring that redirects are safely vetted. In an asynchronous context, the hook should be asynchronous and properly offload synchronous blocking calls (like DNS resolution `socket.getaddrinfo`) to a separate thread via `asyncio.to_thread` to prevent event loop contention.
