## 2024-05-01 - [CRITICAL] Fix Server-Side Request Forgery (SSRF) bypass in Citation Service
**Vulnerability:** The citation service validated the hostname of user-provided citation URLs (`_is_safe_public_host`) before fetching them to prevent SSRF. However, because it only checked the initial URL and allowed `httpx` to follow redirects (`follow_redirects=True`), a malicious user could provide a URL that redirects to an internal, private, or metadata endpoint (e.g., `169.254.169.254`), bypassing the SSRF protection entirely.
**Learning:** Checking the host only once before an HTTP request is insufficient when automatic redirects are enabled. Redirects can point to entirely different, restricted network ranges.
**Prevention:** Always implement SSRF host validation within an HTTP client's request hook (e.g., `event_hooks={'request': [hook_function]}` in `httpx`) to ensure every request—including all redirects—is validated against the safe list. Raise a specific client error (like `httpx.ConnectError` with `request=request`) to block unsafe requests effectively.
