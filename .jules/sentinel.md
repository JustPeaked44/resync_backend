## 2026-09-30 - SSRF via HTTP Redirects
**Vulnerability:** Found an SSRF vulnerability where an HTTP redirect could bypass an initial host validation check and point to internal IP addresses (like localhost/127.0.0.1). This happened because `httpx.AsyncClient` was configured with `follow_redirects=True` but the host validation check was only performed on the *initial* URL prior to requesting it, leaving a "known residual gap" as commented in the code.
**Learning:** `httpx` follows redirects automatically when configured, but its redirect handling does not re-evaluate safety checks applied before the request. To validate hosts across redirects properly, an `event_hooks={'request': [hook_function]}` needs to be attached to the client so the validation fires on every outbound HTTP request.
**Prevention:** Whenever using HTTP clients with automatic redirect following, ensure that host validation logic (like SSRF guards) is applied to *every* request, typically via event hooks or interceptors, rather than just the initial URL check. Always consider the target of a redirect. Additionally, when using `httpx.ConnectError` in modern `httpx` versions, ensure the `request=request` argument is provided to avoid compatibility issues.
