## 2025-02-24 - SSRF through HTTP Redirects in httpx
**Vulnerability:** A vulnerability existed where SSRF prevention only applied to the initial URL provided by the user. If the URL redirected to an internal service or a private IP, `httpx` (configured with `follow_redirects=True`) would transparently follow the redirect, exposing internal services.
**Learning:** `httpx` transparently handles redirects, meaning simple pre-flight checks are insufficient. Asynchronous event hooks (`event_hooks={'request': [hook]}`) in `httpx` are necessary to inspect every request in the chain, including redirects, to enforce security constraints like restricting access to public IPs.
**Prevention:** To prevent SSRF when using `httpx` with `follow_redirects=True`, apply `event_hooks={'request': [hook_function]}` to validate the host before every request, including redirects. Ensure the hook raises a relevant exception (like `httpx.ConnectError` including the `request=request` parameter) if the target is unsafe. Wrap synchronous address resolution checks inside async hooks with `asyncio.to_thread`.
